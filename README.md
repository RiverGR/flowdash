## 0. 프로젝트 개요 (간단 요약)

본 프로젝트는 공통 요구사항을 기반으로 한  
칸반 형태의 태스크 관리 대시보드(Todo-List) 구현 과제입니다.

CRUD, 기간 필터, 통계, 테마 및 UX 요소를 포함하며  
팀 단위 협업을 통해 설계 및 구현을 진행하였습니다.

- 각각의 역할 중에서도 할 수 있는 부분으로 역할을 분배하였습니다.

## 2. 수행 절차 및 방법 (Process & Strategy)

### 2-1. 진행 순서

1. 필수 요구사항 분석, 선택 기능도 가능하면 구현
2. Todo 데이터 구조와 LocalStorage Key 요구사항에 맞게 설정
3. 앱 구조 설계와 디자인 설계
4. 핵심 기능(필터 / CRUD / 대시보드 / 통계) 구현
5. 핵심 UX 기능(닉네임 / 인삿말 / 테마전환)도 구현
6. UI, UX 개선, 버그 수정

### 2-2. 협업

- 기능 단위(닉네임 / 인삿말 / 통계 그 외 등등)로 JS 파일을 분리하여 작업
- 공통 상태와 후에 선택적으로 추가한 기능은 'app.js'파일에서 관리하도록 협의
- UI 모듈은 서로 직접 의존하지 않을 수 있도록 설계
- 변경 사항(pull / push)들은 즉시 팀원 간 서로 공유 후 반영

## 3. 프로젝트 구조

### 3-1. 디렉터리 구조

```
flowdash/
├─ README.md
├─ index.html
├─ css/
│  ├─ base.css
│  ├─ components.css
│  ├─ layout.css
│  └─ modal.css
└─ js/
   ├─ app.js
   ├─ add.js
   ├─ dash.js
   ├─ entry.js
   ├─ filter.js
   ├─ greeting.js
   ├─ nickname.js
   ├─ preload.js
   ├─ theme.js
```

---

### 3-2. 모듈 책임 분리

- `entry.js`: 앱 부팅 관리 및 중복 실행 방지
- `app.js`: Todo 상태 관리 및 생성, 읽기, 수정, 삭제(CRUD), 렌더링 중심 로직
- `add.js`: 할 일 추가 카드 UI와 이벤트 관련 파일
- `filter.js`: 검색, 필터, 정렬 UI 와 정렬 방식 필터링 처리
- `dash.js`: 통계 수치 계산 및 대시보드 UI
- `preload.js`: 할 일 추가 섹션 UI 깜빡임 현상 방지 전용(후에 기능 추가 및 애니메이션 추가하였을 때 UI 오류 현상 방지 파일)
- `theme / nickname / greeting.js`: UX 관련 기능(테마 전환 / 닉네임 변경 설정 / 인삿말 바꾸기)

### 3-3 데이터 흐름

사용자가 입력한 후
→ 상태 변경(`app.js`에서)
→ 로컬스토리지(LocalStorage) 저장
→ 리스트들 다시 렌더링
→ 대시보드 및 배너 UI 부분 갱신

## 4. 핵심 설계 결정 사항 (Design Decisions)

- TODO 상태와 렌더링 흐름을 `app.js`로 단일화를 시켰습니다.
- UI 기능은 저장, 토글, 계산 역할만 담당할 수 있도록 분리하였습니다.
- 로컬스토리지를 상태의 기준으로 사용하였고, 새로고침 후에도 상태를 그대로 유지할 수 있도록 하였습니다.
- 초기 렌더링 이전에 UI 상태를 적용해서 UX 깜빡임을 방지하였습니다(`preload.js`)

## 6. 트러블슈팅 (Troubleshooting)

### 6-1. 새로고침 시 할 일 추가 카드 섹션 깜빡임 현상

- **증상:** 새로고침과 창을 열고 닫을 때 할 일 추가 카드가 '접힘'상태라면 잠깐 펼쳐졌다가 접히는 현상 발생
- **원인:** 접힘 상태가 JS 로딩 이후에 적용되는 것을 확인
- **해결:** 렌더링 이전에 상태를 먼저 적용할 수 있게 `preload.js`로 적용
- **회고:** UX 기능 문제는 구현이 되었다고 해도 반드시 한번 더 점검하여 애니메이션과 기능적으로 정말 문제가 없는지 다시 확인이 필요함을 인식하였습니다.

### 6-2. 앱 중복 실행으로 인한 이벤트 문제

- **증상:** 일부 이벤트 리스너(할 일이 2번 추가된다던가, 닉네임이 2개가 겹쳐서 나오는 현상)들이 중복적으로 발생
- **원인:** 초기화 로직이 여러 경로로 실행이 될 수 있는 구조로 설계가 되었습니다.
- **해결:** `entry.js` 파일을 생성, 파일 내에서 부팅을 예약과 실행을 분리하여서 초기화를 하였으며, 1회만 실행될 수 있도록 하였습니다.
- **회고:** 초기화의 중요성과 중복 이벤트 발생의 치명적인 오류가 있음을 인식하였으며, `entry.js`와 같은 부팅 예약/실행의 기능의 중요성을 인지하였습니다.

### 6-3. 필터 영역의 오류 발생

- **증상:** 검색 및 필터를 임의로 지정하였을 때, 중복으로 저장하면 검색과 필터가 아예 안되고 등록된 TODO 카드들이 나오지 않은 현상이 발생하였습니다.
- **원인:** 필터 영역의 정의를 설정하지 않은 코드를 추가하여서 필터 영역에서 상태나 우선순위 선택을 같이 하였을 때 강제적으로 중단이 되었습니다.
- **해결:** 오류가 나는 필터 부분이 필요한 부분이 아니였기에, 그 부분을 완전히 삭제하고 필터 로직을 다시 생성하였습니다.
- **회고** 조건을 맞추기 위해서는 각각 모든 조건이 역할을 수행할 수 있도록 역할 지정이 필요하다는 것을 인지하였습니다.

### 6-4. css 디자인 밀림 현상

- **증상:** 필터 부분에 쉐브론 화살표가 영역 바깥으로 나가는 현상이 발생하였으며, 할 일 추가 카드 영역에 사용자 입력 칸을 클릭 시에 왼쪽 영역이 조금 잘리는 현상이 발생하였습니다. 추가적으로 TODO 카드의 편집 영역의 요소들이 오른쪽으로 밀리는 현상이 발생하였습니다.
- **원인** 각각 오히려 디자인을 어긋나게 하는 margin과 padding, trenstion을 주었고, 편집 영역은 클래스 선택에 있어서 오류가 났기에 디자인 적용이 되지 않았습니다.
- **해결** 디자인 적용을 잘못하게 하는 margin, padding, trenstion을 삭제하고, 전체적인 css 파일들의 클래스와 디자인을 재검토하였습니다.
- **회고** JavaScript로 만든 기능 구현도 중요하지만, 사용자가 불편함을 느끼지 않도록 디자인 영역의 알맞은 배치의 중요성을 다시 한번 인지하였습니다.

## 7. 자체 평가 및 회고 (Self Review)

### 7-1. 잘한 점

- 역할 분담을 각 섹션과 그 안의 있는 기능 구현으로 중점을 맞추는 작업이 가능했습니다.
- 공통 데이터 규칙(`app.js`)을 기준 삼고 처음에 협의를 하였기에 코드 충돌이 적었습니다.
- 사용자가 어떻게 하면 더 편리하게 볼 수 있을까? 라는 관점을 항상 생각하여 편의성에 중점을 두었습니다.

### 7.2 아쉬운 점

- js 코드 일부에 미래 대비 코드가 존재하는데, 원래는 이것들 부가적인 기능으로 추가하고 싶었으나 추가를 해보았으나 오히려 사용자가 조금 더 불편하다고 의견이 조율이 되어 후에 편의성을 도입한 후 적용할 수 있도록 미래 대비 코드로 남기고 후에 업데이트를 하기로 하였습니다.
- 서로 간의 코드 충돌이 없었으나, 처음 역할 분배에 있어 어떤 분이 일을 더 몰아서 하는 불공정함이 있었으나, 후에 파일 구조 및 역할 분배를 재분배하며 다소 해결하였습니다.
- 처음부터 만들어지지 못한 추가적인 기능(마감일 알람 기능)은 따로 파일을 나누지 못하고 전체 로직을 관리하는 `app.js`에 작성했다는 점이 매우 아쉽습니다.(팀원과의 소통이 조금 부족했던 것 같습니다.)

### 7.3 다음에 개선 할 점

- 미래 대비 코드로 존재하는 js 기능들은 후에 편의성을 고려하여 추가해보기
- 상태 변경 로직의 대한 테스트가 직접 추가를 하여서 테스트를 해서, 후에는 자동화를 시켜보고 싶습니다.
- 디자인적인 요소를 조금 더 개선하여 사용자가 한 눈에 봐도 눈에 불편함과 피로감을 느끼지 않게 조금 더 개선하고 싶습니다.

## 9. 결론

팀원 모두가 이 Todo-list 팀 프로젝트를 통하여 협업 환경에서의 역할을 어떻게 분배해야하는 지 체감하였습니다.
또한 공통적으로 주어진 이 과제를 어떻게 해석하고, 어떻게 구현을 해야하는지 여러 번 고민하게 되는 계기가 되었으며, 이 프로젝트를 구조하고 설계하고 코드를 짤 때에 어떻게 해야 사용자가 더 편리할지, 불편함을 느끼지 않을지 항상 고민하였습니다.
그리고 항상 UI, UX의 디테일이 얼마나 중요한 지 알게 되었으며,
함께 코드를 작성하며 어떻게 해야 서로 코드와 의견에서 충돌이 일어니지 않을 지, 어떻게 서로 의견을 조율하고 코드와 자신의 스타일의 대한 타협을 해야하는지를 인지하였습니다.
